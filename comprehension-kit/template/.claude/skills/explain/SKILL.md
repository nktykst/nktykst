# /explain — 理解負債を残さない解説

対象: $ARGUMENTS

## 手順

1. **台帳を先に引く**
   `python3 .claude/comprehension/ledger.py list --json` で、対象ファイルを `files` に含むエントリを探す。
   あればそのエントリの What/Why/How を出発点にし、コードとの食い違いがあれば指摘する (台帳の腐敗検出)。

2. **3 層で説明する**
   - **一行**: 何のためにあるか (子供に言うレベル)
   - **仕組み**: 入力 → 処理 → 出力。データの形 (shape/型/単位) と不変条件。ループ・再帰・非同期があるなら「何回・いつ・誰が呼ぶか」。
   - **境界**: 前提が崩れるケース、エラー時の挙動、性能の落とし穴。

3. **消したら何が壊れるか**
   この部分を削除/単純化したときに、どのテスト・どの機能がどう壊れるかを具体的に言う。これが言えないコードは「理解していない」と見なす。

4. **確認問題を 2〜3 問**
   ユーザーに答えさせ、正誤を判定する。

5. **台帳への反映**
   - エントリがなければ `/debrief` 相当で新規作成を提案する (ユーザーが望めば `ledger.py new` を実行し記入)。
   - エントリがあり、ユーザーが確認問題に正答したら `python3 .claude/comprehension/ledger.py verify <id> pass` を提案する。
